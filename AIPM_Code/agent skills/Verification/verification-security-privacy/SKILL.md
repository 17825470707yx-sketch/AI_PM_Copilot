# Verification Security Privacy Agent

## 目的

检查需求、接口、数据模型和前端展示是否涉及安全、隐私与合规风险，并给出可执行的脱敏、加密、权限和隐私提示要求。

该 skill 的目标不是泛泛提醒“注意安全”，而是把安全与隐私要求落到字段、接口、页面和测试点上。

## 适用场景

- 需求涉及账号、手机号、邮箱、头像、用户简介、地理位置、支付、组织权限等用户数据。
- 新增或修改 API response、数据库字段、日志、埋点、导出功能。
- 需要判断是否符合 GDPR、个人信息保护法等基本隐私原则。
- 需要给代码生成 Agent 明确加密、脱敏和权限处理规则。

## 输入

- PRD 或需求说明
- 数据字段列表
- API request / response 示例
- 数据库 schema 或模型说明
- 用户权限角色
- 目标地区或合规要求，若有

## 工作流程

1. 识别敏感数据字段：直接标识符、间接标识符、行为数据、业务敏感数据。
2. 识别数据流：采集、存储、处理、下发、展示、日志、导出。
3. 判断权限边界：谁能读、谁能改、谁能导出、谁能删除。
4. 生成脱敏和加密策略：例如手机号掩码、邮箱部分隐藏、密码 BCrypt、敏感配置不入库。
5. 检查隐私提示和用户同意：是否需要弹窗、隐私政策入口、删除/撤回机制。
6. 生成安全验收项和测试建议。

## 检查清单

- API 是否下发了前端不需要的敏感字段。
- 日志、埋点、错误上报中是否包含个人信息。
- 密码、token、密钥是否避免明文存储。
- 用户是否能理解数据如何被使用。
- 是否存在越权访问、越权修改、批量导出风险。
- 是否有删除、撤回、最小化采集的基本说明。

## Guardrails

- 不要泛泛提醒“注意安全”，必须落到字段、接口、日志、权限或测试点。
- 如果目标地区或合规要求未知，必须标注合规假设，不能声称已经满足 GDPR、个人信息保护法等法规。
- 安全或隐私阻塞项优先级高于普通 UAT Go 结论。
